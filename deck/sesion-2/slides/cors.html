A02 · CONFIGURACIÓN INSEGURA · KATA a02_config

Reflejar el origen es invitar a todos

Antes

origen = request.headers.get("Origin")
if origen:
  resp.headers["…-Allow-Origin"] = origen
  resp.headers["…-Allow-Credentials"] = "true"

app.run(debug=os.environ.get("DEBUG", "1") == "1")

Después

if origen in ORIGENES: # lista explícita
  … Allow-Origin = origen; Vary: Origin
X-Content-Type-Options: nosniff
Content-Security-Policy:
  frame-ancestors 'none'
debug = os.environ.get("DEBUG") == "1"

Con el origen reflejado y credenciales, cualquier página que visite Ana puede leer sus pedidos con su sesión.

Seguro por defecto: si alguien olvida la variable de entorno, la aplicación queda segura y no en modo depuración. Reflejar Origin con credenciales es peor que el asterisco, porque los navegadores no permiten credenciales con *: el reflejo esquiva esa protección.
