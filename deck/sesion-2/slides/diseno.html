A06 · DISEÑO INSEGURO · KATA a06_diseno

Ningún escáner encuentra esta falla

Antes

for item in items:
  total += item["precio"] \
       * item["cantidad"]
if cupon:
  total *= 1 - descuento

Después

if not 1 <= cantidad <= 10: → 400
precio = SELECT precio … visible = 1
UPDATE cupones SET usado = 1
 WHERE codigo = ? AND usuario = ?
   AND usado = 0
if rowcount != 1: → 400

No hay una línea «mala»: el error es haber diseñado que el cliente decida. Lo encuentra el modelado de amenazas, no una herramienta.

Por eso A06 es categoría propia desde 2021. El UPDATE con usado = 0 y la verificación de rowcount hacen la operación atómica: dos solicitudes simultáneas con el mismo cupón no pueden ganar las dos (condición de carrera). Con SELECT y después UPDATE, sí podrían.
