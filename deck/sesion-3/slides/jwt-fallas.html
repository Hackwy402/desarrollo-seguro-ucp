Cuatro maneras de aceptar un token falso

Antes

jwt.decode(token, options={"verify_signature": False})  # firma ignorada
JWT_SECRETO = "secreto"                    # se adivina con un diccionario
jwt.encode({"sub": u}, …)                  # sin exp: vale para siempre

Después

jwt.decode(token, JWT_SECRETO, algorithms=["HS256"],
              audience="api-billetera", issuer="billetera-ucp",
              options={"require": ["exp", "iat", "sub", "iss", "aud"]})
JWT_SECRETO = os.environ["JWT_SECRETO"]    # 32+ bytes aleatorios

La cuarta: algorithms ausente. Con llaves RS256, un atacante firma con HS256 usando la llave pública como secreto (RFC 8725).

alg: none no es una curiosidad histórica: sigue apareciendo en librerías caseras y en código que usa decode sin verificar «solo para leer el usuario». La audiencia evita que un token emitido para otra API del mismo proveedor de identidad sirva en la suya.
