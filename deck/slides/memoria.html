SEGURO POR DEFECTO DESDE EL LENGUAJE

~70 %

de las vulnerabilidades graves reportadas por Microsoft y por el proyecto Chromium eran errores de seguridad de memoria.

Por eso CISA y la NSA piden hojas de ruta hacia lenguajes memory-safe (Rust, Go, Java, C#, Python) para código nuevo.

Fuentes: Microsoft Security Response Center (2019) · Chromium Project (2020) · CISA/NSA, Memory Safe Languages (2025)

Elegir el lenguaje es una decisión de seguridad. No significa reescribir todo: código nuevo en lenguajes seguros, y el código C/C++ existente con fuzzing y revisión.
